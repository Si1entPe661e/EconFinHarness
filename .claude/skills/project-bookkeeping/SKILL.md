# Project organization

Use the user's existing system. A small task needs no project files; larger work can use one Markdown note.

- Record the goal, necessary tasks, responsibility and important dependencies.
- Link useful data, code, literature and outputs by path or artid / DOI.
- Update status from actual work, outputs and collaborator reports. Do not mark unexecuted work complete.
- State missing material or decisions that prevent useful progress.
- When moving a file, update links that depend on it.
- Leave research design to the analyst and data or code changes to the implementer.

`templates/project.md` is an optional starting point. Do not require event logs, asset databases or machine state files.

## Skill composition

For compound tasks, consult harness/skill-composition.md and read only relevant skills. For larger tasks, track the necessary dependencies from research choices through samples, methods, inference, presentation and writing using existing files and concise notes. Do not add administrative prerequisites to ordinary work.

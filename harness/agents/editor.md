Own the requested revision level and supplied document. Preserve factual meaning, qualifications, source identity and author commitments. Flag contradictions and unsupported claims instead of filling gaps from memory.

Distinguish structural and substantive issues from style. Use actual source pointers for numerical changes, and format-specific tools for tracked changes or rendering when needed.

Unless its skip conditions apply, run the writing revise module (harness/workflows/revise-writing.md) in its order, or only the requested pass, and return each pass's findings and instance table; if the task contract does not allow the module's reads or scratch files, list the revision as unresolved. Deliver the revised artifact with a concise account of material changes and unresolved issues. Do not trigger unrelated estimation, a review fleet or publication.

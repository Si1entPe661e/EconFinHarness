# Recommended rules: `iv` (draft)

Written by the empirical-analyst role from the method literature in `harness/skills/iv/references.md` and the generated evidence layers: observed code practice (`observed.md`, distillation set of 10 cards; 3 held out in harness/paradigms/iv/reported.md, plus `../shift_share/observed.md` with 3 cards) and reported paper practice (`reported.md`, 32 paper-practice notes after the paper-level hold-out, 29 of them linked to a card). A few pointers below resolve only in `../_all/reported.md`, because `restud_89_1_6` is an input to this method's reported layer but its records are tagged to the shift-share layer; those pointers are labelled `_all`. Observed and reported frequencies are evidence of practice only, not of correctness. Unknown card fields and tags absent from a note are never counted as absence; for IV the first stage is unknown in every card that records a diagnostic, which is why the reporting rules below lean on the paper layer.

## Applicability

- Covered: linear 2SLS with fixed effects and clustered inference, single and multiple instruments, shift-share and leniency instruments, weak-instrument-robust inference.
- Not covered: nonlinear IV and control-function models beyond a robustness mention, many-instrument asymptotics in depth, IV quantile regression.

Design branches used below: (a) binary or discrete instrument with a binary treatment; (b) examiner or judge leniency; (c) shift-share exposure; (d) continuous or multi-valued instrument, or an ordered treatment. Rules `r1a`-`r1d` and `r4a`-`r4d` apply per branch; a design that fits none of them is an unresolved case for the analyst, not a default to branch (a).

## Open questions for review

- Which weak-instrument statistic and which critical value should be the harness default when SEs are clustered (effective F against a stated worst-case-bias critical value, Kleibergen-Paap, or an AR set reported unconditionally). Until this is decided, r9 requires the analyst to declare the statistic and the critical value in the frozen plan, and clause (c) of the r9 validation tests only that a declaration exists with a source, not which value it holds. This item needs a user or reviewer decision, not a corpus count.
- The placement clause of r9 (main table rather than appendix or running text) is `not testable by a template` with the current artifacts, because the card layer has no specification-to-output links in 9/10 cards. It stays a reviewer check unless output artifacts become machine-readable.
- How to record first-stage evidence in cards so that future aggregation is possible (a targeted `first_stage` read in the extraction prompt).
- Shock-level inference implementation across languages (Stata `ssaggregate` versus R `ShiftShareSE`) and their equivalence, which needs a synthetic test before r4c is promoted beyond draft.
- Whether the four design branches in r1 and r4 are the right partition for this corpus, and where a design that fits none of them should be routed. Only branches (a)-(d) are covered by cards here; the branch labels are the author's, not a generated field.

# Report modes

| Report | Useful structure | Checks that matter |
|---|---|---|
| Analytical / evaluation | Question, scope and approach, findings, alternatives, uncertainty, recommendation | Claims use actual results; benchmark and comparison periods match; limitations affect the stated conclusion. |
| Technical / implementation | Problem, resulting behavior, design/tradeoffs, validation, operations and remaining risks | Tested versus proposed behavior is explicit; commands, versions and paths are usable; no test pass is invented. |
| Project / closeout | Outcome versus scope, delivered artifacts, validation, deviations, unresolved items and handoff | Milestone completion has evidence; deferred work is named; owners and next actions reflect actual agreements. |
| Incident / investigation | Impact, observed timeline, contributing factors, recovery, corrective actions | Observation and causal hypothesis differ; unknowns remain visible; fixes have checks. |

A management audience needs implications and decisions first. A technical appendix can hold implementation details. Preserve traceability between the executive summary and supporting sections; shortening a report must not remove a qualification that changes its meaning.

Before delivery, check substantive support and document quality separately. Verify numbers/units/citations; then hierarchy, readability, tables/figures and cross-references. A document can pass formatting checks while its claims remain unverified.

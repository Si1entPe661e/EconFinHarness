# Planning a project

A useful plan names: outcome and audience; deliverables with acceptance criteria; owner; dependencies and source paths; committed or forecast milestones; next actions; and material risks or unresolved decisions.

For a decision, record the question, alternatives considered, selected choice, rationale, evidence and affected deliverables. Preserve the original choice when it changes. Do not ask the user to adjudicate routine implementation details already covered by authorization.

For handoff, include current revision, work completed with evidence, remaining checks, known failures, the next executable action and output ownership. A list of filenames without their status is insufficient; a full transcript is unnecessary.

Use the local runtime only when machine execution or cross-session dependencies warrant it. A document, issue tracker or spreadsheet can be the project system; avoid maintaining conflicting copies of status.

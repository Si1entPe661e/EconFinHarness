# Checklist: literature search and verification

Each item is answered `yes`, `no`, or `unknown`. `unknown` means the available inputs did not settle the question and is never recorded as `yes`. `no` means the check ran and the answer is negative.

Record for each item: the answer and the location (paper list row, search log entry, or claim id).

| # | Item | yes / no / unknown |
|---|---|---|
| 1 | Is the research question or the claim written as one sentence before searching? | |
| 2 | Are the relevance criterion and the support criterion stated separately? | |
| 3 | Was `Paper/*/metadata/articles.csv` searched before any web source? | |
| 4 | Were several query formulations used, and are they all recorded? | |
| 5 | Were per-article directories opened for every corpus hit? | |
| 6 | Is the local code status recorded for every corpus paper, using the fixed vocabulary? | |
| 7 | Were Crossref, OpenAlex, or Semantic Scholar used only after the corpus search? | |
| 8 | Does every delivered reference carry a DOI or an artid? | |
| 9 | Was every identifier read from a source rather than constructed or recalled? | |
| 10 | Is the version checked recorded (working paper, accepted, version of record)? | |
| 11 | If a claim depends on a specific number in a paper, does that number come from the cited version? | |
| 12 | Is relevance recorded separately from support for each claim? | |
| 13 | Is it recorded what was actually read to judge support (abstract, section, table)? | |
| 14 | Does every row carry a verification status from the fixed vocabulary? | |
| 15 | Are `unverified` entries labelled as such everywhere they appear, including in any draft? | |
| 16 | Was every paywall, login, and human verification page respected rather than bypassed? | |
| 17 | Are restricted sources recorded with the link, the restriction, and the date? | |
| 18 | Were request rates kept low and single-threaded against repository APIs? | |
| 19 | Was any paper PDF, dataset, or full replication archive downloaded? (a `no` is required here) | |
| 20 | Does the deliverable include a gaps section listing what was searched with no result? | |
| 21 | Does the gaps section list claims that still have no support? | |
| 22 | Are unresolved candidate references listed rather than dropped? | |
| 23 | Is the assumed scope stated when the requester did not specify one? | |
| 24 | Were support judgements re-checked after the claim text last changed? | |
| 25 | Were audited metadata files under `Paper/*/metadata/` left unmodified? | |

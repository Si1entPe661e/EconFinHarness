# Project status

Report the current state for the audience and reporting period. Inspect existing work before requesting information the files already contain.

- Separate completed and checked, produced but unchecked, in progress, blocked, stale and planned work. A command's existence is not execution; a collaborator's report is attributed until inspected.
- Compare against agreed milestones and scope. Describe what changed, its effect on delivery and the next responsible action. Do not equate task counts with meaningful progress.
- Link key completion assertions to artifacts or check outcomes. Keep unresolved decisions, missing inputs, dependency failures and forecast uncertainty visible.
- Update the user's authoritative system instead of creating a duplicate status ledger. Use `evidence-tracking` when important completion claims span sources or sessions.
- Keep administrative coordination distinct from domain decisions. Route a methodology, product or writing judgment to its responsible capability.

For an executive update or recurring briefing, use `briefing-writing`. For a project replan, use `project-planning`. Do not create a recurring automation unless the user requested one.

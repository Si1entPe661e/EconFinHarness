# Independently reproduce a paper from its text

Use this path when the user asks for an independent or blind reproduction. It complements the analysis workflow without requiring a new agent runtime.

1. **Set the source boundary.** Inventory filenames without opening author programs, notebooks, command histories, saved model objects, or packaged answer tables. Read the paper, appendix and authorized data only. A directory named `input` can contain estimated factors and prepared portfolios; distinguish these from raw observations. Do not use a paper's existing recipe card as a shortcut to its implementation.
2. **Translate the paper into an executable specification.** Record equation/table/page pointers, the estimand, variable mapping, sample restrictions, timing, weights and inference. Match data columns to definitions using units, descriptions and non-estimation diagnostics. A filename such as `main` is not evidence of variable identity. Collate every mention of each variable, sample rule and model term (text, footnotes, table notes, legends, design section, appendix); a difference between mentions is an ambiguity with both readings, and the statement describing coding or the executed design is primary by default. When a concept has several measurements or informants, follow [variable construction](../skills/panel-data-checks-efh/references/variable-construction.md), which also covers identifying a descriptive variable by its published statistics. Where the text is silent about a model term, start from the terms it names plus the main effects needed to interpret them; an added term is a choice whose alternative omits it. When it names no test or covariance, log the design-relevant candidates as an ambiguity; a check that cannot tell them apart does not resolve it. Rank ambiguities by the exhibits they can move and predeclare alternatives for the highest-ranked ones before the first empirical fit.
3. **Declare the feasible starting point.** State which transformations can be independently rebuilt and which depend on supplied intermediate data. A reproduction conditional on supplied portfolios is not a reconstruction of stock-level sorts; a supplied text index is not a rerun of topic estimation. Missing upstream inputs need not prevent downstream work.
4. **Implement with available mature packages.** Check runtime and package availability, retain one main entry point with plain scripts that follow [lean code](../skills/pipeline-review-efh/references/lean-code.md), keep inputs read-only, and save actual numeric results and fitted samples. Keep dependencies explicit. Probe the requested graphics backend by producing a small valid file; an installed function or a capability flag does not establish that its shared libraries load.
5. **Check what can silently change a number.** Choose checks by design: timing and calendar gaps for time series; value domains, stored nonresponse codes and missing propagation in derived indicators for survey and experimental data; merge cardinality and the sample rule everywhere ([panel checks](../skills/panel-data-checks-efh/SKILL.md)). Use small known examples or an independent numerical backend for transformations, weights and estimators written by hand; a mature package's covariance needs the option that selects it, not a reimplementation. Keep these as small inspection scripts beside the specification. For classification, precedence or fallback rules, compare the coded rule with its declared text on a few cases covering each branch. In the pipeline, assert only what the program relies on whatever the paper reports: keys, merge cardinality, arm exclusivity, cluster identifiers, the stated sample rule and the result of each declared cleaning rule (value domain, missing propagation). A fixed bug's check can be a retained inspection run. Give a numerical routine written by hand one negative example that must fail; data guards and run machinery need no tests of their own.
6. **Compare in one place without overwriting the first specification.** Write each exhibit's estimates once to a numeric results file and build the exhibit, with every statistic the paper prints, from that file. One comparison program reads one transcribed target file and applies one rule: half a unit of the last displayed digit, counts exact. Build and exhibit scripts do not read published values, and a published N is compared, not asserted. Say what a match establishes: a matched N fixes the sample, not item coding; a matched rounded mean does not exclude edits below half a displayed unit; a residual gap is attributed to one component only by a check that varies it. Before reporting a variant, confirm on a small known example that its code follows the declared rule, including precedence and fallbacks; if they differ, correct one, record which, and do not describe the coded version as predeclared. If a predeclared variant reproduces a published table, retain the initial result and label the new comparison; numerical correspondence alone does not prove upstream provenance. Mark every specification entry written after the first fit as post-result, explain any post-result change and rerun its affected checks.
7. **Deliver a lean runnable task.** Include the entry point, minimal environment, source-to-result crosswalk, actual output paths and a table of reproduced, conditional and unresolved components. The delivered pipeline builds data, estimates and exports; comparison with published values and inspection programs live in their own scripts. One mechanism guards against stale results: write a completion marker last and remove it at the start, or clear only the derived folders the entry point creates. Stata batch mode exits 0 after an error, so also check the log for error lines. A single reproduction needs no status file or tests of its own run machinery. Each cited check, including an explanation of a residual mismatch, names its retained script or log or is labelled a conjecture ([evidence tracking](../skills/evidence-tracking-efh/SKILL.md)). Before delivery, and at the join when several agents wrote parts of the pipeline, run the [pipeline review](pipeline-review.md) unless its skip conditions apply.

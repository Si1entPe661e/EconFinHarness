# Independently reproduce a paper from its text

Use this path when the user asks for an independent or blind reproduction. It complements the analysis workflow without requiring a new agent runtime.

1. **Set the source boundary.** Inventory filenames without opening author programs, notebooks, command histories, saved model objects, or packaged answer tables. Read the paper, appendix and authorized data only. A directory named `input` can contain estimated factors and prepared portfolios; distinguish these from raw observations. Do not use a paper's existing recipe card as a shortcut to its implementation.
2. **Translate the paper into an executable specification.** Record equation/table/page pointers, the estimand, variable mapping, sample restrictions, timing, weights and inference. Match data columns to definitions using units, descriptions and non-estimation diagnostics. A filename such as `main` is not evidence of variable identity. Record ambiguities before the first empirical fit.
3. **Declare the feasible starting point.** State which transformations can be independently rebuilt and which depend on supplied intermediate data. A reproduction conditional on supplied portfolios is not a reconstruction of stock-level sorts; a supplied text index is not a rerun of topic estimation. Missing upstream inputs need not prevent downstream work.
4. **Implement with available mature packages.** Check runtime and package availability, retain one main entry point, keep inputs read-only, and save actual numeric results and fitted samples. Keep dependencies explicit. Probe the requested graphics backend by producing a small valid file; an installed function or a capability flag does not establish that its shared libraries load.
5. **Check consequential behavior before comparing results.** Use small known examples or an independent numerical backend to check timing, calendar gaps, sample selection, weights, transformations and covariance. Each fixed bug needs a targeted check. A negative example must fail when it violates the boundary or numerical assumptions.
6. **Compare without overwriting the first specification.** Compare full-precision estimates with the paper's displayed precision. State whether a match is numerical, qualitative or unresolved. If another predeclared input variant reproduces a published table, retain the initial result and label the new comparison; numerical correspondence alone does not prove seed-word or upstream data provenance. Explain any post-result change and rerun its affected checks.
7. **Deliver the complete runnable task.** Include the entry point, minimal environment, source-to-result crosswalk, checks, actual output paths and a table of reproduced, conditional and unresolved components. Make a fresh failed run visibly failed so stale successful outputs cannot be mistaken for current results. Separate hard implementation checks from publication discrepancies; a mismatch is not automatically a program bug.

See the independent [War Discourse example](../examples/war-discourse/README.md) for a real-data task with separate text-description and published-table tracks, source guards, numerical checks and explicit missing-input limits. Original third-party programs and data remain outside the public harness.
